Module 1 — The Problem with PPTX

0% Diffable in Git — binary blob, no line-level review
50MB+ Typical deck size with embedded media
1 App required to even open it (licensed, versioned)
∞ "final_v3_FINAL_reviewed.pptx" copies floating around

Why HTML Instead?

1
Plain text — every slide is markup you can diff, review, and merge like code.
2
No proprietary app — opens in any browser, on any OS, forever.
3
Live & embeddable — real code snippets, live charts, video, iframes — not static screenshots.
4
Instant hosting — push to GitHub Pages / Cloudflare Pages, share a URL, no attachments.
5
Themeable at scale — one CSS change rebrands every deck in the repo.

PPTX vs HTML Decks

AspectPowerPoint (.pptx)HTML Deck
FormatBinary ZIP of XMLPlain text (HTML/Markdown)
Version controlWhole-file replace onlyLine-level diff & merge
Review workflowEmail / screen-sharePull request + inline comments
DistributionEmail attachment / file shareURL — always latest version
InteractivityStatic, limited animationLive code, video, charts, embeds
ThemingManual per-deck template editsCentral CSS/theme file
AutomationManual onlyCI can generate/update decks from data

Module 2 — HTML Slide Frameworks

reveal.js

The de-facto standard. Vertical/horizontal navigation, speaker notes, PDF export, plugin ecosystem. This deck is built with it.

Marp

Write slides in Markdown, render to HTML/PDF/PPTX. Great for engineers who think in Markdown.

Slidev

Vue-powered, developer-first. Supports live component embeds and animated code diffs.

impress.js

CSS3 3D transforms for a "Prezi-style" zooming presentation experience.

Anatomy of an HTML Slide


<section>
  <h2>Slide Title</h2>
  <ul>
    <li>Bullet one</li>
    <li>Bullet two</li>
  </ul>
</section>

Each <section> = one slide. Nest <section> tags for vertical sub-slides.

Module 3 — Git-Native Workflow

1
Author slides as index.html / slides.md in a repo.
2
Open a PR — reviewers comment on exact lines, like code.
3
Merge to main — CI auto-deploys to GitHub Pages.
4
Share one permanent URL — audience always sees the latest version.

Module 4 — Migrating an Existing Deck

  1. Export existing PPTX content to Markdown (markitdown deck.pptx).
  2. Map each slide's text/media into a Marp or reveal.js section.
  3. Re-theme with CSS instead of manually re-styling each slide.
  4. Replace static charts/screenshots with live embeds where possible.
  5. Commit to Git, open a PR, publish via Pages/Cloudflare.

Hands-on Lab

Exercise

1. Fork this repo.
2. Duplicate a <section> and edit its content.
3. Commit with a descriptive message.
4. Open a PR and request review from a teammate.
5. Merge and view the diff — notice it reads like code, not a blob.

Key Takeaways

HTML slide decks bring presentations into the same review, version-control, and deployment pipeline as software — diffable, hostable by URL, and infinitely more automatable than a binary .pptx file.
